五模块并行，双 Barrier 收敛

将 cost 分支与 CAS 输出成本控制能力合并；彻底移除 37 叶运行时，把并发严格限定为五个模块 Editor/Auditor 与五个模块级 Cross owner，之后串行进入 Chief、Final 与 Delivery。

结论

目标架构已实现，且没有以删减专家正文、Reviewer 或最终门禁换取成本。 37 个小节编号仍保留为报告 taxonomy、Claim 与 finding 的定位坐标，但不再产生独立 Agent、Task、Session、Lane、Wave 或恢复状态。

成本控制的核心从“37 叶并行放大”改为“固定 5+5 并发上限、精确恢复、输出单副本视图”。Chief、Final、Delivery 保持串行。

运行面缩减

10k+旧运行、合同、恢复与测试行被删除

删除 three-wave/leaf 调度、leaf contracts、leaf checkpoint 与对应运行测试；新增 Cross owner 与 CAS 安全链。

确认后的唯一工作流

语义不变量

  • 模块作者一次提交完整模块，37 小节仅作为内部结构与 coverage。
  • 每个模块使用稳定 Auditor identity；修订后必须由同一 Auditor recheck。
  • Cross owner 只写本模块；其他四模块为 hash 绑定的只读 compact views。
  • 无 finding 的 Cross owner 也产出可验证 no-op completion。
  • 任一 owner 失败会 drain 全部五项、记录 terminal，并阻止 barrier 与自动重发。
  • 两个 barrier 均要求当前 run、精确五项、refs / hashes / revisions 一致。

CAS 输出控制链

  1. Single writer：workspace lock → run lock，防止不同 run 覆盖共享 Outputs。
  2. Output owner：completed result 与 receipt/version/hash 耐久后，原子发布 Work/output-owner.json。
  3. Completed-run compactor：默认 dry-run；仅显式 run_id + apply 才将最终 DOCX 转为相对 CAS symlink view。
  4. Fail closed：active/non-completed、owner mismatch、receipt/version/hash/CAS tamper 均拒绝。
  5. Rollback：从只读 blob 原子恢复普通文件；journal 支持 rolled_back / recovery_required。
  6. v3 mixed storage：仅 CAS-mode artifact 要求 blob ref；materialized artifact 保持本地实体，兼容 v2 只读验证。

为什么不直接自动压缩全部 Outputs

  • 首轮只处理写入路径已证明原子替换的最终 DOCX。
  • 不删除 CAS blob，不迁移 receipt/version，不改变 completed 判定。
  • source-index DOCX 等写入器尚未逐个证明 symlink-safe 前，不进入自动视图。
  • 成本收益需在副本物理回收后实测；CAS view 设计本身不等于费用下降。
