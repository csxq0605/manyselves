01 · Executive verdict

有大量重复，但不是一种重复

Provider 请求、工作流阶段与存储闭包各自有不同的浪费机制；必须分层治理，不能靠统一缩短提示词或压低输出上限解决。

审计结论 · YES

高频工具跟进和重复 schema 是上下文主风险；最终 DOCX 的多份物理副本是样本存储主风险。

153 次工具跟进占全部调用的 80.1%；模块编写与修订合计 153 次、约 6.461M tokens。样本闭包中存在 28.51MB 字节级精确冗余，其中同一最终 DOCX 的副本贡献 88.38%。

可立即控制的是：重复 schema、无信息增量的继续、可判定的同一校验失败、可安全识别的传输重试，以及同内容多路径物理复制。

07 · Failure semantics

先判定请求处置，再决定是否重试

09 · Experimental controls

本轮改动：减少重复，不削弱判断

实验按可独立回滚的控制点拆分；只有通过离线故障注入和真实 Provider 配对门槛，才能宣称“节省且不降质”。

已落入实验工作树并做定向离线验证

  • A
    原子化上下文压缩

    assistant tool-call 与匹配 tool-result 成对保留或成对移出；摘要保留最新引用、状态与下一动作。

  • B
    旧结果片段只恢复、不重写

    同运行且可验证的历史结果映射为 already_ready；模型可见历史去除退休标记，避免模仿和循环写入。

  • C
    Provider-visible 与 Knowledge 双向隔离

    canonical Provider messages、tool args/schema 和工具结果在请求前统一清除退休标记；Knowledge 在 snapshot 发布与加载两端做语义 sentinel gate，hash 自洽也不能放行污染正文。

dirty experiment 已实现；真实 Provider 待验证

  • D
    Provider disposition / no ambiguous retry

    显式区分 not_sent、definitely_rejected、accepted_or_unknown；处置不明不发第二个物理请求，409 不盲目自动重试。

  • E
    类型化、进展感知的有界继续

    首个续片允许；此后必须出现新的 durable 状态或新语义事件，并受分类回合上限与无进展上限双重约束；不通过统一降低专家 max_tokens 控成本。

  • F
    四个 workflow 入口恢复 request cost mode

    不再把请求统一改写为 observe；强制模式仍必须只在类型化提交/检查点等安全边界暂停。

  • G
    默认路径撤回 37-leaf 放大

    默认恢复冻结实验提交的五模块级协作与串行 Cross owner；37-leaf / lane 路径只在显式 bounded_module_lanes 下启用，Chief 与 Final 仍顺序执行。

  • H
    Provider pre-send / terminal journal

    manifest v3 绑定 run、task 与 task-attempt；先恢复 hash-verified completed terminal，否则同任务 pending 或 accepted_or_unknown 会在进程崩溃恢复时 fail-closed，不悄悄创建第二次物理请求。

不做的优化：删除关键角色上下文、截断专家输出、跳过 Cross/Chief/Final、用 lint 代替语义审查、把一次正常工具继续误判为失败、或在流处置不明时盲目重试。这些手段会把“成本下降”换成“失败率上升”。
仍待实现：ambiguous journal 的显式 reconciliation UI/API、journal rename 的父目录 fsync（当前只承诺进程崩溃恢复，不宣称断电耐久）、并发 lane 共享的 429 cooldown/admission、workspace 级 single-writer/output-owner，以及真实 Provider 配对。
10 · Anthropic harness mapping

把公开工程原则映射到运行时控制点

这里引用的是 Anthropic 官方工程文章与 Claude Platform 文档；映射是本项目的工程推论，不代表官方对 Manyselves 的结论。

simple patterns

最简可组合工作流

固定、可预测的阶段用代码路径；真正需要模型判断的步骤保留 agent 灵活性。并行只用于可独立拆分的广度，不把所有阶段都展开。

context

最小高信号上下文

引用先于整文，按需加载；压缩保留结构化进度、关键 ID、校验状态和下一动作，而不是把所有历史再次发送。

tools

少而清晰的工具接口

按角色暴露工具，减少重叠 schema；工具返回支持过滤、分页和紧凑摘要，并保持错误信息可行动。

durable progress

增量进度与恢复

以持久化结果、检查点和功能门禁作为真实进度；新上下文先读状态再做下一项，避免猜测与重复工作。

errors & streams

区分错误和流状态

429 服从退避，409 先协调；中断流根据已接收块类型处理。不可把“响应处置不明”折叠成普通安全重试。

evals

评估最终环境状态

同时记录 pass@1、总 attempts、tokens、工具错误和最终交付状态；不能用“多试几次最终成功”隐藏首轮失败成本。

11 · Phased plan, gates & rollback

先对齐契约，再兑现成本

指标口径与限制

calls / tokens：取自最新成功运行的 usage 账本聚合；阶段 token 以报告给出的三位小数百万值展示，因四舍五入与总量可能有微小差异。

重复 schema：重复工具 schema 字符数 / 工具 schema 字符总数；不等于全部请求字符或全部输入 token 的重复率。

精确冗余：样本闭包内按字节内容完全相同计算；不包含语义相似但字节不同的文本，也不代表全项目。

非 A/B：旧运行与本运行并非同输入、同配置、同执行路径的受控配对。当前实验 dirty tree 未运行真实 Provider 配对基准。
