1 · 启动

启动调用链

关键实现点

  • RuntimeHost拥有总生命周期；启动顺序为 bus → loop manager，停止时先停生产者/loop，再停 bus。
  • LoopManager只创建一个长期 AgentLoop("main")；没有 Provider 时进入 degraded，不启动专业 loop。
  • 常驻 Main system prompt 是三段拼接：业务路由 prompt、Common prompt、报告包 main-agent prompt。这个组合是当前 P0 耦合点。
  • 报告专业 Agent 并不在启动时存在，而由每个 workflow 的 ReportingAgentRunner按 identity_key 创建。

prepare_run 的真正含义

  1. 生成 report-<uuid10>。
  2. 写 Work/runs/<run>/request.json。
  3. 确定显式输入：source Markdown、已有模块 refs 等。
  4. RunInputSnapshotStore.freeze 冻结三个 scope：Inputs、Knowledge、Templates，外加显式 refs。
  5. 每个文件入 ContentAddressedStore、创建可信 handle、链接到 frozen-project/<logical_ref>，最后提交 inventory digest。
  6. 真正执行前再获取项目级写租约、run 锁；同一项目同时只允许一个有写操作的报告 job。
恢复语义： 同一 run 再次执行不会重新冻结新文件；它必须继续使用原 inventory。补充资料通过 typed supplements/决策流程进入，不应静默替换冻结输入。

4 · 主流程

报告主流程状态

ReportWorkflowRunner.run 顺序

  1. 建立预算 ledger 与 provider attempt guard。
  2. 恢复成本边界；执行/恢复 Preparation。
  3. Evidence readiness gate。
  4. 阶段 checkpoint 后执行成本边界策略。
  5. 校验固定 Template Role Skill bundle。
  6. 构建模块 Knowledge 上下文与 ModuleDispatchPlan，写 handoff contracts。
  7. 运行目标模块 lanes；子集则交付后返回。
  8. 五模块全量时运行 Cross owner pipelines。
  9. 运行 Chief 章节 lanes，并确定性保护/装配第二章。
  10. 运行 Final 章节审计；只返工受影响章节。
  11. 引用绑定、结构校验、Markdown/DOCX、来源索引、delivery receipt。
  12. 仅在未挂起时关闭 workflow 身份；恢复时复用仍保留身份或 completion。
5 · Agent 合同

Agent 有效合同组成

静态层解决什么

角色、职责范围、候选工具、模型参数、memory/background、逻辑 reads/writes。它是身份不变量。

动态层解决什么

本次任务目标、当前 phase、可见 subject、可读制品、精确输出 Schema 和 revision。它是任务变量。

开发常见误区： frontmatter 的 reads/writes 是逻辑 carrier 声明，不是文件系统 ACL；frontmatter 的 tools 是候选全集，不代表本次 TaskRegistry 一定暴露。

提交工具的关键行为

  • 每个 task 只注册当前允许 output 的 submission schema；模块号、chapter、revision、finding 数量等会被固定为 const/精确约束。
  • 长正文不能直接塞进最终 JSON；必须先用 write_result_part 写入当前 task/revision 的固定目录，再以 artifact ref 提交。
  • submit_result 要求字段直接位于顶层，禁止用通用 payload 包装绕过 schema。
  • 模块正文的 E-* 绑定由运行时读取 part sidecar 并生成 Claim；模型不能自造 Claim marker。
  • 验证失败会返回结构化修复指令；重复同一错误受到次数和指纹门禁。

去事实化边界

  • 只迁移“观察 → 证据限定 → 结论 → 原因 → 影响 → 行动”的写作与审查方法。
  • 不得复制客户名称、数值、项目问题、原结论、原行动内容和证据编号。

11 · 专业技能

模块专业技能解析与治理

解析优先级

packaged → product → project；同一 skill_id 后加载层覆盖前层，因此 project 最高。

加载范围

模块 Specialist 获得本模块拥有的全部 active Skills；模块 Auditor 按固定模块和目标小节过滤；Cross/Chief/Final 不自动继承。

发布治理

显式反馈意图 → candidate → non-regression evaluation → 用户确认 → immutable SkillVersion → active manifest；可 rollback。

产品级治理状态机

Template Role Skill 不进入这条产品专业 Skill 演进链；项目 Main 也无权直接发布产品版本。
12 · 知识库

专业知识加载与项目事实边界

来源与冻结

  • 项目：Knowledge/（随 run input snapshot 冻结）。
  • 全局：可选 GlobalKnowledge，由 Knowledge builder 建独立快照。
  • 同相对路径时项目知识优先。
  • 拒绝 symlink/path escape，解析文本并去重。

检索与预算

  • 按固定 taxonomy id/title 进行确定性相关性排序。
  • 当前模块上下文预算约 14,000 chars。
  • 单 snippet 约 900 chars；每子模块最多 3 个文档片段。
  • 来源注册为 R-*，上下文写入 current-run context 文件。
事实权限： R-*、W-*、Template Skill、Domain Skill 和模型知识都不能把某个事实写成“该客户已发生”；项目事实必须有当前 run 的 E-*，没有则按 missing evidence policy 写成待核实、低置信度或未评估。
13 · 模块流程

模块专业流程内部顺序

并发与 reducer

  • 五个 ready lane 同时获得业务调度资格，ProviderAdmissionController 另行限制全局/provider-model 并发（当前默认 8）。
  • 每个 lane 内作者和 Auditor 串行闭环；不同 lane 可以并发。
  • 一个 lane 失败时先 drain sibling；RecoveryStateStore 保留已完成 lane，只重试失败 lane。
  • 只有目标 lane 全部 terminal，Reducer 才写 module aggregate 并允许 Cross。
  • 模块审查有机器 preflight，但机器通过不能替代语义 Auditor。
14 · 跨模块流程

跨模块责任流程

关键约束

  • 每个 owner 从同一冻结的五模块批准快照开始，避免 reviewer 看见不同版本。
  • related 四模块只读；finding 只能写回 owner 模块。
  • owner 作者修订后，必须由原模块 Auditor 做局部回归；之后原 Cross owner 才能语义关闭。
  • 无 finding 也必须产生 no-op completion，保证五路 barrier 完整。
  • 快 owner 可先进入自己的局部闭环，不必等待慢 owner 完成 initial review；最终仍需五 owner barrier。

17 · 恢复

并发、恢复、结果复用与成本记录

恢复原则

  • UI checkpoint 不是恢复源；lane/aggregate record 才是。
  • 已完成 task 的 input contract、execution profile、lease epoch 和 result 必须一致，才允许直接复用。
  • Finding、completion、review artifact 使用不可变写入；恢复重复写只允许字节/模型一致。
  • 失败重试按 lane/affected chapter，不允许把整个阶段重新作为“一个大任务”重放。
  • Main exception 只能在 private-lane cohort 排空后序列化执行，避免在并行作者/审查者运行中改变全局决策。

成本控制实际语义

UsageLedger记录 input/output/cached tokens、schema chars、重复字符、持续时间和估算费用；StageCostController在安全阶段边界 observe/warn/pause。当前预算 snapshot 明确标记 limits_enforced=false / hard_request_limits_enforced=false，因此不要把 max attempts/tokens 对外描述成“每次请求硬截断”。
