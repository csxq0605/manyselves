# PR #6 规则核查与正文绑定语义更正

## Claims 的生产含义需要更正

沿 `ModuleSubmissionInput → SubmitResultTool._assemble_module_commit/_assemble_module_revision_commit → _runtime_claim_for_part` 核查，当前作者已经只提交正文 parts、E-ID绑定及紧凑提交信息。运行时把每个完整小节包装为一个 `technical_interpretation` Claim；其 confidence 来自绑定证据的解析元数据。这不是作者对小节中每条事实、风险和建议做了独立语义分类。

因此上一轮以内部 ClaimRecord 字段说明“当前作者仍重复提交语义Claims”的推论不成立；不能仅从内部存储模型推导模型输出负担。旧手工/历史Claim的语义字段仍需保留，但当前生成的整段绑定也不能当成逐项质量覆盖。

本轮改动：

- 新生成的整段绑定显式保存 `origin=runtime_part_binding`；未标注的旧记录为 `unspecified`，不猜测其生成方式、不重写历史文件。
- 初审、局部回归与复审视图保留该来源；运行时绑定的审计 confidence 为null，避免将解析置信度显示成专业判断可信概率。完整正文、来源和未解决状态仍保留。
- 原始证据包增加当前 `bound_submodule_ids`，从当前审查范围内Claims反向投影。空列表只表示该E-ID未被当前正文绑定，null表示旧输入没有计算该映射。复审仍包含未引用事实，以及已从当前绑定移除但旧finding要求核对的来源。
- 有绑定不等于已判断/已有行动，缺绑定也可能是别名或其他来源支持同一对象。没有自动新增finding、阻断门禁、专业阈值或模型阶段；审计提示明确以上边界。

## 当前自带的八份方法文件

这些是仓库分发的方法文件，不是旧真实项目蒸馏出的14份角色Skill。逐份阅读后的处置如下：

| 文件 | 核查结果与处置 |
| --- | --- |
| 2.1/system-architecture.md | 删除“低于100%绝不能判过载”的绝对表述；要求核对计算口径、额定基准、运行条件及设计/制造商依据。 |
| 2.2/environment.md | 保留测点/环境/温升区别、原测量与局放方法/位置要求；没有写入统一工程阈值。 |
| 2.3/protection.md | 保留保护定值证据、剩余电流不能直接推定原因、SPD状态与限值分开。 |
| 2.4/configuration.md | 删除无来源的80%提示线及100%绝对禁判条件；改为根据工况、降额和适用依据说明容量余量/风险。 |
| 2.4/installation.md | 保留行与图绑定、NG缺图明确复核；NG记录本身仍保留，不直接判定故障种类。 |
| 2.4/operating-condition.md | 10A只作为已有S4-4附图/复核规则，不表述为法定安全限值；仍要求原因排查。 |
| 2.4/field-inspection.md | 保留对象/部位/原始坐标，单一测点温度不能推出缺陷等级；照片缺口保持可见。 |
| 2.5/operations.md | 保留具备性与有效性分别核查，不从文件名生成制度内容。 |

上述修改撤销缺依据的通用要求，没有设置替代工程阈值，也不等于完成全部专业标准验收。
