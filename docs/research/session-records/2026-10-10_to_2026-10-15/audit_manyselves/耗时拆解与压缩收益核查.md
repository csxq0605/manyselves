# 耗时拆解与压缩收益核查

日期：2026-10-11。审计对象是已有历史日志；没有重新调用模型生成报告。压缩修复前基线 `fb0ded3`。原始运行记录未修改。

## 压缩的目的仍然成立

语义摘要用于保存阶段性结论，并减少后续请求重复携带旧原文的负担。本次没有取消默认摘要。仅看“摘要花了很多 token”无法认定其无用；应该比较摘要成本与后续上下文的净减少，同时检查结论、约束、证据引用是否保留。

之前新增的 `structured_handoff` 只是可选对照策略，不能代替这个评估，也不是本轮性能优化的推荐默认。

|错误/自动重试请求|2 / 2|9 / 9|

时间口径：由每条账本的完成时刻减 `provider_active_ms` 推算请求区间。观测跨度不包括首个请求之前的准备和最后请求之后的渲染，也不等同严格端到端交付时间。并行请求会重叠，因此 97.82 分钟不能当作删除摘要后可省下的墙钟时间；9.94 分钟同样不是优化收益下限或上限。

`queue_wait` 也不覆盖所有等待其他任务、退避或中断的时间。全报告观测跨度内约 10.05 分钟没有账本可见的活跃请求，修订约 20.42 分钟；不能仅凭这份账本把全部空档归因为某一种原因。全报告并行同时活跃数最高为 5，证明并行确实在发生，但每条分支内部仍有串行写作、摘要、工具跟进、修订和审阅依赖。

全报告摘要输入的缓存 token 比例只有约 1.07%，普通工具跟进约 63.02%。两者来自既有账本字段，不是按价格计算的费用；未查询或假定模型单价。

还有估算偏差：既有 Runtime 使用每字符 0.3 token 的启发式。此样本中，成功摘要请求的实际输入 token / 请求字符数中位数约 0.433，普通工具跟进约 0.480。统计分母含序列化请求包装，与 Runtime 内容计数字段不完全相同，不能据此直接替换成统一常数；但足以提示配置阈值不是实际 tokenizer 计数。该误差尚未修复，仍需校准。

全报告后段的两个 Chief Agent 从约 19:47 开始，到约 20:22 / 20:23 才结束，之后末次 Final 请求到 20:26。这个长尾说明只加快前段并行作者无法消除全部等待。必须同时减少串行无效轮次并检查生成与修订负担。

## 摘要有没有真正减轻后续负担

按同一 Agent 的时间顺序，取相邻摘要之间的正常请求数：全报告共 100 组可观察间隔，79 组仅隔 1 个正常请求，另有 2 组间隔为 0（包含摘要失败重试）。这体现频繁重压缩。

118 组有相邻正常请求的摘要，其摘要后第一次正常请求与摘要前最后一次正常请求的输入 token 比值，中位数约 1.013。修订样本为约 1.022。这不是严格无压缩对照：两次请求之间会新增工具内容、可能跨任务边界、且少数失败项采用估算。它只能说明日志没有呈现理想的“摘要后输入明显下降且维持多轮”现象，不能算出取消摘要的净收益。

本地源码测试进一步确定了三个具体预算缺陷：

1. 36,000 是触发阈值，也是压缩后填满历史的目标，因此留不出下一轮空间。
2. 最近任务消息在历史填满后补回，未扣除已占用预算；测试的 1,800 目标实际返回 2,178 估算 token。
3. 先按程序摘要大小选择历史，再替换成模型摘要，未重新计算；测试中压缩后达到 4,388，高于 4,096 触发线。

还复现了第四点：仅有一条必须保留的巨大当前任务时，也会付费做摘要，但任务原文仍必须保留，结果并未缩小。

## 已修复并做同输入比较

默认继续使用模型语义摘要。触发线仍为 36,000，压缩后目标改为其 60%，即 21,600 估算 token，比例可配置。先为当前任务和最新完整工具交互留预算，再选旧消息；模型摘要生成后按实际摘要大小重新选取历史。没有任何旧内容可移除时，不做徒增开销的摘要请求。

|固定工具序列、相同模拟语义摘要|修复前|修复后|
|---|---:|---:|
|36,000 阈值 / 100 轮：摘要次数|81|9|
|同上：正常请求累计输入估算 token|3,243,586|2,644,956|
|同上：送入摘要方法的历史估算 token|3,040,876|337,162|
|4,096 阈值 / 60 轮：摘要次数|53|14|

正常请求累计上下文估算量下降 18.46%；摘要次数也明显下降。两版使用同一个固定模拟摘要，并保留同样的阶段性决定。测试还检查了最新工具调用/结果不被拆开、摘要中的语义决定与准确引用保留。

相关测试 109 项通过；配置、会话恢复及 RuntimeServices 补充选择 15 项通过，两批有重叠。修改文件 Ruff 与暂存差异空白检查通过，沿用对两个既有异常类命名 N818 的排除。

**这些是离线机制结果，不是实际模型 token、秒数或报告质量的提速结论。** 摘要方法历史估算不含其最终包装和全部摘要指令。模拟摘要不会随输入变化，无法评估真实摘要遗漏或后续额外重读。更小的历史保留量可能增加语义摘要依赖，这是必须在真实生成中检查的代价。

## 验收还没做完

当前配置的模型地址为外部 MiMo 服务 `token-plan-cn.xiaomimimo.com`，没有把它假定为已批准的内网环境，也没有向其发送客户资料。真实对照需要明确可用的推理环境和数据范围。

下一项应在相同模型、相同冻结输入、相同提示词及工具权限下，仅改变压缩策略参数，记录请求级总耗时、普通请求/摘要请求 token、重复读取、超时/恢复，以及 14 条剩余电流、13 条测温、9 条 SPD 的保留与引用支持。质量不下降且端到端时间/token 有净收益，才能接受性能优化。较小的局部对照仅说明该范围，不能代替全报告验收。
