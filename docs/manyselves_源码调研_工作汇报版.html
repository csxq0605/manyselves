固定角色技能

包括 5 份模块作者技能、5 份模块审查技能、3 份总编章节技能和 1 份成稿审计技能。

当前结构。 用户请求由常驻主控接收；报告主流程负责资料冻结、任务顺序、并行汇合、权限和恢复；专业 Agent 负责模块分析、审查、总编和成稿审计；最终文件由确定性程序装配和渲染。

  • 跨模块审查完成记录和跨模块决策包。
  • 总编章节结果、成稿审计结果与最终审计快照。

  • 证据与来源索引 Markdown 与 DOCX。

系统分层

当前运行架构

启动顺序是：桌面入口创建 RuntimeHost，初始化项目结构与日志，构造共享 MessageBus 和 LoopManager；先启动消息总线，再启动 Agent 循环。报告任务由 Main 调用 Workflow Tool，工具控制器把任务登记到 TaskBoard，再由 ReportingService 与 ReportWorkflowRunner 创建专业身份。

重要区分： GUI/TaskBoard 的状态不是恢复权威；workflow-state.json也只是 UI 投影。真正的 lane/aggregate 恢复由 RecoveryStateStore 管理。

五类报告任务入口

操作真实调用链关键边界

常驻主控先选择任务入口，再调用报告工作流工具。模板角色技能生成与报告写作是两个独立任务；报告写作只读取固定路径中已经生成并通过完整性校验的角色技能。

执行顺序

完整报告执行顺序

运行前置步骤

  1. 生成稳定 run_id，持久化 request.json。
  2. 冻结 Inputs/、Knowledge/、Templates/ 以及显式引用，形成内容哈希、可信句柄和 inventory digest。
  3. 获取项目级写租约和 run 级排他锁，防止同一项目多写任务并发覆盖。
  4. 从冻结快照构建 manifest；要求唯一 S4-6 工作簿作为当前 run taxonomy。
  5. 确定性解析文档/表格/图片，规范化为 E-*，建立照片—证据邻接，计算覆盖度。
  6. 证据准备状态决定继续执行、等待用户补充或按用户选择处理。

阶段完成条件

每个模块只有在模块审计事项经原模块作者修订、原模块独立审计身份复核并全部关闭后，才写入模块审计完成记录；五个模块均完成后才通过五模块完成门。每个跨模块责任审计流程只有在跨模块审计事项经原责任模块作者修订、原模块独立审计身份完成局部回归闭环、原跨模块审计复核并全部关闭后，才写入责任流程完成记录；五个责任流程均完成后才通过跨模块完成门。总编和成稿审计按章节形成完成记录；交付阶段要求公开输出文件可读取，且当前运行写入 delivered 状态。

上下文加载

角色技能、专业知识与项目证据

模板角色技能

回答“怎么写、怎么审”。 来自指定模板的一次性蒸馏，去除客户事实、数值、标准阈值和原结论。固定写入 Work/report-template-role-skills。

模块专业技能

回答“本专业按什么方法分析”。 版本解析优先级为 packaged → product → project，后者覆盖前者；只有 active manifest 生效。

专业知识与项目证据

Knowledge 是 R-* 专业参考；Evidence 是 E-* 当前项目事实。 Knowledge 不能替代 E-*，模型世界知识也不能被写成客户事实。

运行机制

当前运行机制

机制当前实现在报告流程中的表现
用户入口与专业任务分离一个常驻主智能体连接报告工作流；专业身份由智能体运行器按任务创建。用户对话持续存在，模块作者、审查者、总编和终审按当前任务范围工作。
五模块并行与完成门五个专业模块 lane 独立执行，完成后由模块汇总器形成统一阶段结果。跨模块审查只在目标五模块均具有有效完成记录后开始。
作者修改与原审查者复核审查事项、作者响应和复核结论分别持久化，同一审查身份负责复核。作者提交修改不直接关闭事项，后续阶段读取审查完成记录。
按章节执行总编与终审第一章、第三章和可选第四章分别运行；第二章五个专业模块由运行时保护装配。终审发现事项后，只返回并重跑有事项的章节。
恢复状态与界面状态分离恢复状态存储保存 lane 和阶段汇总记录；工作流状态文件用于界面投影。恢复同一次运行时，已完成且合同一致的结果直接复用。
任务级制品能力当前任务引用被规范化为具体文件类型、可执行操作和交付方式。内联和哈希保留内容不可再次打开；引用交付内容按文件类型授予读取能力。
运行输入冻结Inputs、Knowledge、Templates 和显式引用在建立任务时形成不可变快照。同一 run 后续恢复继续使用原快照，不读取工作区中后来变化的文件。
技能、知识与证据分层模板职责技能、模块专业技能、R-* 专业参考和 E-* 项目证据分别加载。不同身份收到不同上下文；项目事实引用当前 run 的 E-* 证据。
